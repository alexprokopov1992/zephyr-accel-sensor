# Датчик движения и датчик наклона на акселерометре

Драйвер реализует две разные функции поверх одного физического акселерометра:

- **датчик наклона** - отслеживает изменение направления вектора силы тяжести относительно сохраненного эталона;
- **датчик движения** - отслеживает быстрые изменения ускорения относительно сохраненной базы.

Оба режима используют одни и те же данные акселерометра, но интерпретируют их по-разному. Наклону важен угол. Движению важен динамический скачок ускорения.

## Получение данных

Акселерометр опрашивается с периодом `sampling-period-ms`. Значение по умолчанию задано в devicetree binding и равно `20 ms`.

Активный путь обработки:

1. данные приходят через `SENSOR_TRIG_DATA_READY`;
2. если data-ready не сработал, используется fallback-таймер;
3. значения `X/Y/Z` переводятся из `m/s^2` в доли `g`;
4. дальше один и тот же сэмпл используется для логики наклона и движения.

В коде это находится в `accel_process_sample()`.

## Режим наклона

Для наклона используются:

- `ref_acc_tilt` - эталонный вектор положения;
- `last_acc_tilt` - последний измеренный вектор;
- warn-зона;
- main-зона;
- текущие уровни чувствительности;
- флаги активной тревоги.

При постановке режима наклона в охрану драйвер сбрасывает `ref_acc_tilt` и через `ARMING_DELAY_SEC = 10` секунд фиксирует текущее положение как эталонное.

Дальше код сравнивает не координаты напрямую, а угол между двумя векторами:

```c
pow_cos_theta = cospow2_between_vectors(data->ref_acc_tilt, current_acc);
```

Если угол превысил warn-порог, вызывается warn-trigger. Если угол превысил main-порог, вызывается main-trigger, и режим переходит в alarm.

### Пороги наклона

Пороги наклона построены как угловые зоны:

```c
static float warn_zone_start_angle = 1.0;
static float warn_zone_step_angle = 2.0 / 9.0;
static float max_angle = 10.00;
```

То есть минимальный warn-порог начинается примерно с `1 degree`, а сетка зон доходит примерно до `10 degrees`.

## Компенсация дрейфа для наклона

Для наклона есть отдельная подстройка эталонного положения.

Таймер `refresh_current_pos_timer_handler_tilt()` раз в `REFRESH_POS_TIME = 3600` секунд пытается обновить `ref_acc_tilt`, но только если:

- режим наклона находится в `ARMED`;
- нет активного warn/main alert;
- текущее положение отличается от эталона меньше чем примерно на `0.5 degree`.

Это нужно, потому что положение автомобиля может медленно меняться без реальной тревожной ситуации. Например:

- изменилось давление воздуха в колесах;
- изменилась высота пневмоподвески или воздушных компенсаторов;
- автомобиль медленно просел или перераспределилась нагрузка.

Такие изменения не должны бесконечно держать датчик в тревоге. Поэтому наклон умеет медленно принимать небольшое изменение положения как новую норму.

## Режим движения

Датчик движения использует отдельные поля:

- `ref_acc_move` - эталонный вектор для движения;
- `last_acc_move` - усредненный текущий вектор;
- `gravity` - сохраненный модуль гравитации;
- warn/main зоны движения;
- счетчики и суммы для усреднения.

Движение проверяется в `process_move_mode()`.

Сначала код усредняет несколько сэмплов:

```c
#define MOVE_SENSOR_SAMPLE_TIME 20
#define MOVE_SENSOR_SAMPLE_COUNT 5
```

То есть окно движения составляет примерно `5 * 20 ms = 100 ms`.

После этого считается разница между текущим усредненным вектором и эталоном:

```c
accelerate = last_acc_move - ref_acc_move;
accel = vector_length(accelerate);
```

Полученное значение сравнивается с warn/main порогами движения.

## Пороги движения

Warn-пороги движения задаются в долях `g`:

```c
static const float warn_zone_accel_mult = 0.006f;
static const float warn_zone_step_accel_mult_step = 0.002f;
```

Примерная сетка warn-зон:

| Индекс | Порог |
| --- | --- |
| 0 | 6 mg |
| 1 | 8 mg |
| 2 | 10 mg |
| 3 | 12 mg |
| 4 | 14 mg |
| 5 | 16 mg |
| 6 | 18 mg |
| 7 | 20 mg |
| 8 | 22 mg |
| 9 | 24 mg |

По умолчанию выбран индекс `5`, то есть около `16 mg`.

Main-зона движения строится выше warn-зоны с зазором:

```c
#define MAIN_ZONE_MOVE_GAP_STEPS 2
```

## Компенсация дрейфа для движения

В датчике движения тоже есть подстройка, но она отличается от подстройки наклона.

Код сравнивает текущий модуль вектора ускорения с сохраненным `gravity`:

```c
change = (data->gravity - acc_len) / data->gravity;
```

Если изменение меньше `border_move`:

```c
static const float border_move = 0.003f;
```

то есть меньше примерно `3 mg`, код считает это не движением, а допустимым малым дрейфом. В этом случае он сразу обновляет базу:

```c
data->gravity = acc_len;
data->ref_acc_move = data->last_acc_move;
```

Если изменение больше `3 mg`, тогда код уже проверяет, превысила ли разница warn/main порог. Если превысила - вызывается соответствующий trigger.

Главный вывод: датчик движения специально не должен реагировать на очень медленные и маленькие изменения. Он должен реагировать на динамику: толчок, вибрацию, удар, быстрое смещение или короткое ускорение.

## Движение в disarmed-состоянии

Есть отдельная логика `process_disarmed_move()`.

Она используется, когда оба режима находятся в `DISARMED`:

- `mode_tilt == ACCEL_SENSOR_MODE_DISARMED`;
- `mode_move == ACCEL_SENSOR_MODE_DISARMED`.

Схема похожа на обычный motion-режим:

1. усредняются 5 сэмплов;
2. считается разница с `ref_acc_move_disarmed`;
3. изменение меньше `3 mg` принимается как новая база;
4. если изменение превышает warn-порог, вызывается `disarm_move_handler`.

## Постановка и снятие с охраны

### Наклон

Режим наклона управляется через `ACCEL_SENSOR_MODE`.

При переходе в `ARMED`:

- сбрасываются текущие уровни зон;
- сбрасываются alert-флаги;
- `ref_acc_tilt` обнуляется;
- через 10 секунд текущее положение фиксируется как эталон.

При переходе в `DISARMED`:

- останавливаются таймеры наклона;
- режим переводится в disarmed.

### Движение

Режим движения управляется через `ACCEL_SENSOR_MODE_MOVE`.

При переходе в `ARMED`:

- период обработки устанавливается в `MOVE_SENSOR_SAMPLE_TIME = 20 ms`;
- сбрасываются счетчики усреднения;
- сбрасывается `ref_acc_move`;
- сбрасывается `gravity`;
- через 10 секунд текущее состояние фиксируется как база.

При переходе в `DISARMED`:

- период обработки возвращается к `ACCEL_SENSOR_SAMPLE_TIME = 1000 ms`;
- сбрасывается disarmed-reference;
- запускается инициализация disarmed-движения через `ARMING_DELAY_SEC_DIS = 1` секунду.

## Адаптация чувствительности после тревоги

После срабатывания warn/main датчик временно снижает чувствительность, чтобы не генерировать постоянные повторные тревоги на одном и том же событии.

Для наклона это делает `coarsering_tilt()`.

Для движения это делает `coarsering_move()`.

После этого таймеры постепенно возвращают чувствительность к выбранным пользователем настройкам:

- `increase_sensivity_timer_tilt`;
- `increase_sensivity_warn_timer_move`;
- `increase_sensivity_main_timer_move`.

## Как правильно проверять

### Проверка датчика наклона

Для датчика наклона подходит простая механическая проверка:

- закрепить плату на длинном рычаге;
- выставить начальное положение;
- поставить режим наклона в охрану;
- после задержки инициализации плавно менять угол по транспортиру;
- проверить warn/main срабатывания.

Это хорошая методика, потому что датчик наклона действительно измеряет изменение угла относительно сохраненного вектора гравитации.

### Проверка датчика движения

Для датчика движения транспортир и очень плавное наклонение подходят плохо.

Причина: motion-логика адаптируется к малым изменениям до `3 mg`. Если менять положение очень медленно, код может принять это как новый baseline, а не как движение.

Для проверки движения лучше использовать:

- короткий толчок платы или корпуса;
- легкий удар по кронштейну;
- вибрацию;
- быстрое малое смещение;
- маятник;
- каретку или другой механизм с контролируемым коротким ускорением.

Проверять надо именно динамическое событие, а не медленное изменение угла.

## Итог по сомнениям

Датчик движения действительно является акселерометрическим детектором ускорения. Для акселерометра это естественная задача.

Но motion-режим нельзя проверять так же, как tilt-режим. Наклон проверяется углом, а движение - коротким изменением ускорения.

Подстройка под дрейф в motion-режиме есть, но она не такая, как у наклона:

- у наклона reference обновляется редко и по угловому критерию;
- у движения reference обновляется быстро, если изменение меньше примерно `3 mg`.

Поэтому медленный дрейф из-за давления в колесах или пневмоподвески критичен прежде всего для датчика наклона. Датчик движения должен реагировать на быстрые динамические изменения, а не на медленное изменение положения автомобиля.
